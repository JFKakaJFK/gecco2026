## Documenting code

Generally, the names of code constructs should convey the intended meaning well enough so that it is not necessary to describe what the code does. This also prevents issues where the code is updated but not the comments documenting what the code does. However, especially for complex logic or if assumptions are at play, the reasoning behind this should be documented directly in the code.

# Solutions

A solution at the minimum needs to store the decision variables to optimize and the quality or fitness thereof. To enable common solution types across algorithms and domains, the solution type holds all supported types of decision variables, and quality types are polymorphic (i.e. anything goes). In addition, solutions can hold additional extensions, for example to support domain specific mechanisms that are stateful or to track additional statistics.

The quality should contain everything needed to make preference decisions between two solutions and all state that is derived during evaluation (e.g. linear scaling parameters) to prevent potentially bug prone side effects. Conceptually, the assumption is that if a solution quality is backed up, the solution is modified, evaluated and the change is reverted, overwriting the quality with the backup should lead to a valid solution state. In the case of symbolic regression, storing the linear scaling parameters outside of the quality could lead to a mismatch as the linear scaling parameters would be modified as a side-effect of evaluation which is not corrected for by solely reverting the modifications to the solution and overwriting the quality with the backup. Note that this assumption is not compiler enforced.
